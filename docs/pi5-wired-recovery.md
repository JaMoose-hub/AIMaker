# Pi 5 插線後的板邊拒絕與局部定位恢復

## 修正範圍

2026-09-22 的 C920 實拍中，Pi 模型仍找到板身（分數約 0.54），但彩色線材與
PCB 色彩遮罩相連，使輪廓填充率只有 0.482 且碰到搜尋區邊界。原本的
`pcb_boundary_unverified` 分支只嘗試可選的全景搜尋，沒有使用現有的局部
參考圖匹配；因此未開啟全景搜尋時，會錯失仍有足夠板面特徵的場景。

現在的流程：

1. 保留原本輪廓拒絕：不降低 0.65 填充率門檻、不接受搜尋框作為實際板邊。
2. 使用**當前畫面的模型 bounding box** 限定局部 SIFT 搜尋範圍，不採用被拒絕的
   模型四角生成 GPIO，不額外執行 ROI 模型。
3. 沿用既有參考圖、互相匹配、RANSAC、16 內點、0.18 覆蓋率、至少 3 象限、
   重投影與幾何檢查。通過才恢復有語義方向的板框和 Profile 腳位。
4. 局部匹配失敗時才嘗試既有全景備援；全部失敗仍顯示 searching，清除主定位器
   的舊位置。Hybrid 的特徵備援必須有同 frame ID、時間戳、pins 及 outline。
5. 即時追蹤原有的同幀光流與有限有效期維持不變；拒絕的模型結果不能更新有效期。
   部分遮擋時仍可依當前影像追蹤，移除／遮住板子或有效期到期則隱藏腳位。

未修改模型權重、CUDA 設定、相機、GPIO Profile、前端、眼鏡 YOLO-only 路徑或接線規則。
無 ROI 模型但有參考圖的 Pi 設定會延遲建立局部匹配器；換板、換相機與關閉時清理狀態。

## 診斷與耗時

`pose_quality.reference_recovery.scope = rejected_boundary_roi` 表示使用此路徑。
`boundary` 保留被拒絕的色彩輪廓資訊，`accepted`、`reason`、`inliers`、`coverage`、
`error_px`、`ms` 說明特徵匹配結果。Hybrid 備援也失敗時保留此資訊。
使用即時追蹤時，模型結果在 `pose_quality.model_source.quality` 內；外層的
`tracking` 是當前影像追蹤狀態，兩者不可當作同一項指標。

反向最近鄰比對只計算通過原本 0.72 比值測試的候選，不再計算必定丟棄的描述子。
仍為精確 L2 brute-force，不採近似匹配、不減少特徵點，也不改動門檻。
在同張存檔影像的離線回放中，70 個匹配／60 個內點／0.216 覆蓋率／0.281 px
匹配誤差不變，暖機後局部匹配由約 118–127 ms 降至 87–89 ms。
這不包含模型推論，也不是端到端 FPS 或實際 GPIO 接點誤差；即時多模型並行仍可能較慢。

## 已完成驗證

- 無私有影像依賴的回歸測試：彩色線材污染輪廓、四個旋轉方向、重用／無 ROI 模型、
  空白／綠色背景／鏡像／小區塊誤匹配拒絕、換相機／換板清理、乾淨板邊不進備援。
- 精確比對等價測試：隨機描述子、有匹配、重複與平手、無關資料、單一鄰居。
- Fresh fallback 檢查：過期 frame／timestamp、缺 pins／outline 不可冒充新定位。
- 本機 C920 靜止插線場景：修正前 40/40 筆 searching；重啟後 40/40 筆 locked，
  再取樣約 39.5 秒、240 個不同畫面，240/240 持續顯示 40 個 GPIO。
  後者仍有 44 筆配對的模型結果為 searching；當前畫面的光流與有效期檢查維持顯示，
  不是宣稱每次模型都能重新定位。
- 瀏覽器接線頁可見藍色板框、GPIO 與原有接線紀錄；700 個中英文 key 檢查和 production
  build 通過。既有 bundle >500 kB 提示未在此工作改動。
- 最終相關回歸測試 185 項通過；完整後端測試 1,707 passed、2 skipped、7 failed。
  7 項失敗在修改前 HEAD 的獨立匯出也可重現，涉及本機設定預期與已退役 HW-123／IMU；
  此工作沒有修改那些功能或宣稱完整測試全綠。

私有實拍、回放和測試紀錄留在忽略目錄 `runs/pi5-wired-diagnosis-20260922/`。

## 尚未完成的實體驗收

目前是單一固定擺位的改善，不是全角度、全遮擋或接線正確率認證。
仍需實體慢速移動、重新進入畫面、不同插線密度和角度測試。
腳位由 Profile 幾何推算；被接頭遮住的接點沒有直接視覺驗證。
定位成功與匹配誤差低都不能證明實際接線、供電或功能正確。
