# 聊天式接線除錯：實作及驗證

日期：2026-10-04。範圍：原助手對話中的拍照邀請、逐張拍照、分析入口、照片依據與人工決定；桌面與手機共用。

## 完成行為

- 「請 AI 幫忙」的拍照邀請保留在助手訊息內，提供「拍照檢查／稍後」。共享聊天不再掛載常駐接線核對面板、「查看核對」入口或第二個輸入框。
- 固定引導由持久流程狀態產生：Pi 第一側 → Pi 另一側 → 零件接頭。明確送出照片即採用該輪該視角並接下一問，不再要求額外選用照片。收齊後由桌面明確按「開始核對」。
- 分析先回覆整組摘要，優先核對異色、腳號未知或候選不唯一的線路，再提供「接對／接錯／不確定」。照片、取景示意、候選及框選細節按需展開。
- 一般文字提問不推進拍照、確認接線或啟動硬體測試。切換圖片、閱讀 AI、重新整理也不等於人工確認。
- 手機同步同一則問題，提供串流、拍照及對話。分析、人工確認及硬體重測仍由桌面處理。
- 操作引用綁定 conversation、epoch、message、flow、review、revision、round。照片提交與人工操作各自去重，過期結果不得覆寫目前輪次。實際改線建立新照片輪次並清除受影響确认與測試有效性。
- 人工提交另存精確收據與本地 outbox；已保存但 ACK 遺失時先讀取原 request 的收據。只有與原明確人工操作、接線版本及照片輪次完全相符的收據可以恢復確認，不採用任意 AI 觀察或伺服器表格。

沿用既有模型、影像預處理、局部裁切及地端線色比較。未訓練新模型，未變更照片判斷為電氣證明。

## 瀏覽器整合情境

使用真實 `UnifiedAssistant`、`AiDebugPanel(chatGuidance)`、`useAssistant`、`MobileWebApp` 與 `useMobileBrowser`，連到 127.0.0.1:18810 的封閉合成 transport。它沒有雲端模型、真實相機或 Pi API 的轉送路徑。手機視窗為 390×844；未使用實體手機相機。

| 情境 | 觀察結果 |
| --- | --- |
| 邀請與聊天入口 | 拍照邀請在原助手訊息內；開始後只出現當前一張照片問題。桌面 textarea=1，常駐核對面板=0，照片訊息內巢狀捲動區=0；未送草稿保留。 |
| 手機拍照及雙端续接 | 原生檔案選擇器提交合成照片；直接追加使用者照片及 Pi 另一側問題。兩端同步，沒有額外「使用此照片」操作；手機無分析或人工確認按钮，沒有橫向溢出。 |
| 收齊與明確分析 | 三張有效照片、零人工決定、零分析提交時顯示「開始核對」；明確操作後僅一筆合成分析，結果摘要在人工回答之前出現。 |
| 人工紀錄、一般提問及遺失 ACK | 第一筆接對只由明確按鈕記錄，其他線未確認；可穿插一般文字提問。第二筆人工決定先保存再回 500；只 GET 原 request 收據，不新增第二筆人工 POST，恢復後下一問可繼續。確認 timestamp 及 guide 表與原提交相符。重新整理後聊天及人工回答歷史保留。 |
| 證據區域與接線新輪次 | 百分比框選保存原圖引用及範圍；局部補拍只更换 Pi 另一側，沒有自動分析。明確開始分析後，操作「我已改線，重新拍照」建立新輪次、清空本零件確認與照片組；舊照片與回答留為只讀歷史，兩端回到 Pi 第一側。 |
| 手機失敗與同一照片重試 | 注入照片採用失敗；原照片與手機文字草稿保留，提供「重試這張照片」。重試沿用同一 dialogue request_id 與 asset，沒有第二次上傳或重複採用；成功後直接進 Pi 另一側。 |

### 瀏覽器預覽的證據邊界

該次執行版本的合成 expected 腳位使用固定示例值，因此它不驗證實體腳號正確性。裁切存儲／無自動分析在瀏覽器中有驗證，但該預覽當時保留舊分析結果；真正後端局部重拍／裁切與分析失效另由 pytest 案例驗證。這兩處預覽原始碼已修正，**未再執行**，遵守 100 次上限。此預覽不會進入 production bundle。

桌面預覽只覆蓋共用訊息與操作傳輸；完整 `useMaker` 的本地作品儲存及真 Pi 工作區沒有用合成頁面替代驗證。人工確認保存的後端持久化、收據與版本防護由目標測試覆蓋，實體手機 Safari 相機、真實線材辨識及電氣／功能測試仍待實機驗證。
