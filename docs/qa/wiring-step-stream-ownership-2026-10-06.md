# 接線下一步與手機串流

2026-10-06。只處理串流生命週期，不變更接線、辨識模型或 GPIO 判定。

## 證據

- 服務初始狀態為 `stream_stopped`；這個狀態本身無法證明是哪個頁面或事件送出停止。
- 使用者確認手機已重新整理，因此沒有將故障歸因於快取。
- 使用者重新開啟串流後，在其 Chrome 現有作品操作：開始、四條超音波接線的下一步、稍後測試並切換到螢幕。這六次操作期間 generation 維持 13，接收影格由 1269 增至 3284，末次影格年齡 16 ms；桌面可見相機影像。本次沒有重現「每次下一步都斷線」。未執行硬體功能測試或宣告新的接線確認。
- 程式中找到確定缺陷：`BrowserPublisher.stop()` 在未啟動相機時也發出不具發布者識別的 DELETE；同一配對的舊頁面、清理程序或延遲要求都能停止別頁建立的串流。新增測試先在原碼重現失敗，不能據此斷言這是使用者所有斷線的唯一原因。

## 修正

- 每次 Start 建立獨立 publisher ID；正常停止、啟動失敗及相機中斷清理只作用於該 ID。
- 尚未建立遠端發布、或已停止的頁面不再發出 DELETE。
- 後端在同一非同步鎖內檢查發布者並完成 start/stop，阻止晚到的停止要求關閉新 generation。
- 舊版無 ID 停止僅能作用於舊版無 ID 串流；不能停止新版串流。
- 若清理發現發布權已移交，不得觸發自動重新啟動搶回串流。
- 保留同作品步驟更新不中斷相機、舊照片定位票失效、明確停止功能及既有 FrameBus。
