# Pi 5 接線照片輔助核對

## 功能與入口

既有 AI 助手的 `AiDebugPanel` 增加「接線照片輔助核對」。主動檢查、測試失敗後進入助手，都使用同一張卡和既有 `/api/debug/sessions`。選定零件後開始收集照片；`initial_action: collect` 不會呼叫模型、拍照或啟動硬體。

卡片依序收集 Pi 第一側、Pi 另一側、零件接頭。使用既有手機／Webcam 影格與倒數拍攝。照片保留原始像素尺寸、雜湊和來源，框選使用原圖正規化座標；查看、切換及框選不會將接頭指派成 GPIO。原圖在既有照片紀錄中保留。

首次分析取得三個角色的接頭觀察；之後只送已變動的視角，沿用未改變的觀察。切換零件可共用同一輪 Pi 照片。按卡片、查看照片、人工確認及重新整理不重新推論。連續兩次補查沒有增加可用依據，改為要求人工沿線核對。

每條線分開顯示預期腳位、Pi 候選、零件候選、線色比較與下一步。相同線色、多候選、未知腳號及遮擋都不等於接線正確；`same_wire` 保持未確認，既有嚴格照片符合條件不放寬。

只有「我已親自確認接對」會寫入現有 guide 確認。「仍無法確定」及「我發現接錯」會撤回該條既有確認，保留 AI 原始觀察；撤回或準備改線先經既有工作停止核對。真正改線後才建立新輪次，舊照片不參與新輪分析；可清除單一零件或全部相關人工確認及測試有效性。重測仍由使用者明確啟動既有零件測試。

## 實作位置

- `backend/app/guided_wiring_review.py`：照片組、候選比較、人工複核與輪次規則。
- `backend/app/debug_sessions.py`、`backend/app/api/debug_sessions.py`：接入既有工作階段、請求去重、版本與晚到結果檢查。
- `frontend/src/components/WiringReviewCard.tsx`：拍攝示意、原圖框選、逐線卡與三種人工決定。
- `frontend/src/components/AiDebugPanel.tsx`、`frontend/src/lib/debugSessions.ts`：對話內操作、保留現有拍攝／測試途徑。
- `frontend/src/lib/wiringReviewGuide.ts`：明確人工操作才變更確認，完整重算原有測試綁定。

## 影像尺寸與限制

零件全景採短邊最多 1080；Pi 全景採長邊最多 1920；局部圖保留原像素，不向上放大。這是可驗證的初始配置，未宣稱為最佳值。每次雲端輸入保留來源與裁切資訊。

自動框選只接受與原圖同影格、尺寸一致且有獨立定位依據的區域。既有投影 pin hints 不能作為驗證；一般側拍在缺少可靠定位時使用完整照片／人工框選。此次沒有訓練或宣稱完成可靠的 Pi 側面自動定位模型。

照片與 AI 輸出不能證明線材導通；真實腳位、漏掉接頭、誤導提示及最終接線判斷仍需人工真值。測試未操作 Pi GPIO。

## 驗證入口與已知範圍

- `npm run test:wiring-review`：卡片、原圖座標換算、人工確認及對話整合測試。
- 在 `backend` 工作目錄執行 `.venv/Scripts/python.exe -m pytest tests/test_guided_wiring_review.py`：涵蓋同色多線、異色、未知腳號、遮擋、分壓、局部重拍、版本過期及人工紀錄。
- `frontend/tools/wiring-review-preview.mjs`：只有模擬資料的 loopback 操作頁，不代理正式 API，不連接硬體或雲端。桌面與 380px 手機操作、拖曳框選、照片切換、確認不自動重測及新輪次已用瀏覽器檢查；截圖位於 `runs/guided-wiring-ui/`。
- 新增功能測試及正式建置結果以本次執行紀錄為準。完整前端回歸目前另有 Eye、舊導覽／重新開始按鈕、手機狀態文字的失敗；沒有將整套測試標為通過。完整記錄位於 `runs/guided-wiring-frontend-tests.log` 及 `runs/guided-test-*.log`。

真實照片比較會分別記錄原圖與混合尺寸的耗時及觀察差異。沒有人工核對過的完整接線表時，不計算接線準確率；使用者補拍次數及完成核對總時間需由實際操作驗收取得。

- 新前端功能：39 passed；TypeScript、i18n、Vite 正式建置通過。建置仍有既有大檔案分包提醒。
- 完整前端回歸分組執行仍有 21 項其他失敗：Eye 顯示 3、舊接線重新開始 4、Maker 導覽 13、手機狀態文字 1。各分組日誌保留；未宣稱全部通過。
- `agent-browser` 檢查了實際助手容器樣式，包含初始卡片可見性、380px 無水平溢出、照片查看與裁切錯誤回復。驗證是隔離模擬資料，沒有把 UI 測試算成真實硬體測試。

同模型實測：`gpt-6.1-sol / low`，Pi 兩側加 HC-SR04，三张歷史原圖。地端準備 0.423 秒、雲端往返 121.403 秒、此條件總時間 121.874 秒。兩張 Pi 圖各保留 11 個線色候選，精確 Pi 腳號全部未知；HC 觀察為 VCC 黃、TRIG 紅、ECHO 藍、GND 黃。這是模型觀察，沒有人工真值，因此不是辨識率。

混合尺寸條件在 37.995 秒後被模型容量限制拒絕；此失敗時間不是推論時間。沒有混合尺寸結果，不能得出較快或品質達標的結論。紀錄與原圖雜湊位於 `runs/gpio-photo-poc/guided-review-benchmark-20261004-02/report.json`。前置嘗試發現的雲端 tuple schema 不相容已修正，另加回歸測試，失敗紀錄保留於 `guided-review-benchmark-20261004-01`。

載入狀態：目前 8100 服務仍為啟動時的舊版 API。嘗試在確認無進行中的除錯、零件測試及 Pi 工作後重啟，遭自動核准審查以「政策阻擋」拒絕，未停止服務。需手動重啟後端並重新整理頁面，才能使用新版流程。

## 深色卡片樣式修正

使用者回報深色助手中出現白底淺色文字。實際頁面確認：`--panel-bg` 未定義，卡片背景回退 `#fff`，但文字沿用深色的 `--text`。`--button-bg` 同樣沒有定義。

`frontend/src/components/wiringReview.css` 已改用專案的 `--surface-card`、`--ink-primary`、邊線及狀態配色；一併修正原圖框選 dialog、數字輸入框、hover 及人工選中按鈕。照片與線材顏色未修改。

正式建置與 14 項卡片測試通過。重新整理使用者目前的 `http://127.0.0.1:8100/` 後，深色卡片背景為 `rgb(18,20,27)`、文字為 `rgb(232,234,240)`，已確認可見；只操作頁面檢視，沒有拍照、模型呼叫或硬體測試。

隔離 UI 使用真實主題 CSS 驗證：深色卡片對比 15.29:1、淺色 18.55:1；人工選中按鈕、錯誤提示、裁切視窗及輸入框可讀。380×820 下頁面、卡片與視窗無水平溢出，沒有瀏覽器錯誤。截圖與指標保留於 `runs/guided-wiring-theme-fix/`；此驗證使用模擬資料。

## 按需展開接線核對

完整核對卡改由 `WiringReviewEntry` 管理：正常對話僅保留「檢查接線」入口，點選只展開介面；原卡的開始、拍照、分析及重測仍各自由使用者操作。目前工作階段的有效無回波／螢幕異常結果、綁定目前作品的既有診斷，或最新 AI `inspect_wiring` 建議可以提供折疊推薦，聚焦相關零件。套件、權限、連線與程式問題優先沿用既有排查，未知原因不直接推薦接線。

測試證據須符合目前作品與接線 key，不能使用已失效結果；新有效測試不被舊診斷覆蓋。已有未完成核對可恢復；收起保留已掛載卡片、照片與人工進度，同輪輪詢／遲到分析不能強制重開。完成最後一條人工確認保持展開，讓使用者接著選擇重測或收起；刷新時已完成人工核對的輪次預設收合。

驗證使用真實 `AiDebugPanel` 與記憶體模擬工作階段，包含正常入口、失敗推薦、缺套件不推薦、只描述症狀不直接判定接線、開始操作、人工確認、收起重開與明確重測。深／淺色桌面與 380px 寬度無水平溢出，無瀏覽器錯誤。截圖與指標位於 `runs/guided-wiring-activation/`，隔離服務禁止連接正式 API；未呼叫雲端或硬體。

目前正式頁面已重新整理，確認正常狀態只顯示小入口；手動展開、收起已實際操作，沒有開始工作階段、拍照、分析或測試。正式建置、i18n 檢查及接線／對話／除錯相關測試通過。既有後端載入限制仍依前述紀錄，本次修改為前端入口與狀態管理。
