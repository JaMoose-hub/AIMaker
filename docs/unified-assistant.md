## Demo

02 的「體驗 AI 設計 Demo」開啟獨立工作區、獨立草稿及對話身分。原作品與相機仍掛載；返回不取消背景工作。

1. 初始兩則訊息標示「示範對話」。清單區分需求、實際電子零件、結構件、僅供概念圖的馬達。
2. 確認內建示範：只讀取固定資料與 `/demo/distance-monitor-three-wheel-motors-v2.png`，沒有模型或生圖呼叫。
3. 自由文字：只以受限制的文字模型規劃清單，不呼叫設計／生圖服務。清單版本增加、舊確認失效；舊成果可展開查看。
4. 清單修改後，內建按鈕會要求還原固定清單；不把舊圖當作修改後成果。
5. 確認 AI 生成：凍結已確認清單版本，經既有設計與圖片服務產生「未套用預覽」，使用 AI 額度。重複相同確認不重送。
6. 「使用此作品」是另一個明確確認：核對 Pi／測試／trial／除錯狀態、備份原作品、建立新作品與對話，進入 01 藍圖。過期版本、背景生成、備份失敗、未知硬體狀態均不採用。

只有電子目錄內的 HC-SR04+ 與 MRD-TFT240 會加入接線、測試和程式；控制器固定 Raspberry Pi 5。馬達只屬概念圖，不能自動行駛。一般新作品沒有新增清單確認關卡。

## 服務與保存

`AssistantService` 在 `backend/runs/assistant/` 原子寫入 JSON；歷史匯入先備份到 `imports/`。前端 `useAssistant` 位於 App，階段切換不換控制器。沒有新增資料庫、雲端儲存或模型 SDK。

| 介面 | 用途 |
| --- | --- |
| `POST /api/assistant/conversations` | 以穩定 ID 建立或讀取（重試安全） |
| `GET /api/assistant/conversations/{id}` | 分頁歷史與作業狀態，`before` / `limit`（最多 100） |
| `POST .../{id}/messages` | 接受文字與凍結當下的階段、作品版本、語言、目標、程式、接線與紀錄 |
| `POST .../{id}/import` | 舊設計／除錯對話備份、去重匯入；缺少時間不補造時間 |
| `POST .../{id}/confirm` | 核對清單版本，內建或真正生成 |
| `POST .../{id}/restore-checklist` | 還原固定清單並增加版本 |
| `POST .../{id}/reset` | 清除聊天上下文或封存上一輪接線／除錯／執行訊息 |
| `POST .../{id}/jobs/{job}/retry-image` | 只重試既有生成工作的圖片 |

依 AI generation persistence 原則，在模型或能力交接前保存工作 ID、請求 ID 及版本快照。相同請求去重；保存可取得的模型與回應 metadata，用量或費用未知時為空，不計成零元。既有設計服務現在也保存純文字工作的結果。

模型取得最多 20 則近期相關訊息及結構化狀態。硬體摘要取伺服器快照，過濾敏感欄位；階段提供預設上下文，不是能力限制。02/03 的自然語言路由最多一次能力交接，不開循環。明確硬體操作仍走原有按鈕與護欄。

後端重啟時，能找到既有設計／除錯工作就核對；不明結果標記 `unknown`，不自動重送。晚到成果留在原對話／版本，只在版本仍吻合時成為目前預覽。清除對話只增加上下文 epoch，不刪原始訊息或作業。重新接線封存舊輪次，舊結果不當作本輪證據。

瀏覽器偏好鍵：`boardvision.assistant.v1`（正式對話）、`boardvision.assistant-demo.v1`（Demo）、`.open`／`.draft`、`boardvision.assistant-width.v1`、`boardvision.code-height.v1`。待確認送出識別放在 `boardvision.assistant.v1.outbox`；並不自動重送。作品仍用原本 maker 儲存鍵。

02 的相機／2D 圖與接線卡之間可上下拖曳分隔線，比例另存於 `boardvision.guide-height.v1`，不沿用舊版左右寬度偏好。雙擊或 Enter 還原，↑／↓ 微調，Shift 加大調整，拖曳時 Esc 取消且不收合接線卡。兩區保留最小高度；收合接線卡時相機使用完整工作區，窄版或高度不足時保留自然捲動排版。調整只改 grid 高度，不重建相機或更改作品與接線狀態。
