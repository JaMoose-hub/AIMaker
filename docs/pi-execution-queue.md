# Pi 連線與共用執行佇列

Pi 連線移到頂部，與 AI 模型選單同層，四個階段共用同一份連線狀態。

## 操作

1. 在上方按「連線 Pi」。
2. 在接線引導按零件測試，或在部署頁按「部署並執行」。送出的是當下程式／接線快照，後續編輯不會偷偷改掉排隊內容。
3. 請求依伺服器收件順序排隊。新工作的環境檢查成功後，如已有程式執行，頂部「執行管理」顯示交接確認。
4. 按「確認停止目前程式，接著執行」後，核對舊程序確實停止，再開始下一個。
5. 未開始的工作可取消；部署上傳／檢查中不硬中斷。零件測試中止保持「無法判定」，不冒充通過。

作品通常持續執行，因此不是無限等待程式自然結束：使用者確認後才停止並交接。每次同意綁定當前 service invocation 或測試 run ID；對象改變會重新詢問，不沿用舊同意。

## 保留的行為

- 原作品不因測試自動恢復，程式與部署檔案不被零件測試覆蓋。
- TFT 仍需本次測試碼與顏色目視确认；取消等待確認的測試不記成通過。
- 斷線／停止結果不明時阻擋後續啟動，重新核對遠端狀態。
- 不停止非 Board Vision 程式。未受目前後端管理的遠端測試阻擋啟動，不用 wildcard 強制清除。
- 不改辨識模型、腳位、供電、BLK 或作品警告門檻。

## 工程範圍

- `PiExecution` 串接既有 `PiDeployer` 與 `ComponentTests`，統一 `/api/pi/deploy` 和 `/api/pi/component-tests`，不是兩個互不相識的工作池。
- 使用者動作透過 `/api/pi/execution/{job_id}/action` 的 `confirm`／`cancel`。
- 相同 request ID 冪等，未完成的相同 payload 去重；最多 16 件未完成工作。多分頁使用同一後端的 FIFO。
- 正式作品 unit 使用 `/usr/bin/flock --nonblock --no-fork <remote_dir>/component-tests/hardware.lock`；與零件 runner 同一把鎖，涵蓋程序存活期間。鎖由程序退出釋放，不能以刪除 lock file 方式解除。
- 這不是跨多個後端的分散式 FIFO。跨後端的遠端 flock 防止新版本程序同時占用硬體，但排隊順序以單一 Board Vision 後端為準。
- 舊版作品需下一次正常部署才換成含 flock 的 unit；新測試仍先檢查、要求確認並停止既有作品。
- 佇列存在後端記憶體；瀏覽器重整／切頁不清除。後端重啟取消未開始的請求，不保存或自動重播部署程式。已執行的遠端作品與保存的測試狀態照原流程核對。
- 舊後端沒有 `execution` 欄位時，新 UI 不送出測試／部署，提示重啟，避免以舊 API 繞過 FIFO。

## 驗證

自動化：FIFO、先檢查環境再停止、雙向交接、失敗與失聯、同意失效、多分頁去重、取消、後端重啟與舊狀態核對、正式 unit 共用鎖；前端固定連線位置、單一狀態輪詢、交接提示及舊 API 阻擋。

隔離 UI：`python -m tests.component_test_preview` 使用模擬 SSH 與合成影像，於 `127.0.0.1:18763` 驗證。不能作為實體 GPIO 或 TFT 功能通過證據。

實體驗收待操作：作品 → HC／TFT → 作品，確認每次交接後只有一個 Board Vision 程序使用硬體，並確認測距與螢幕實際反應。
