- `App` 只持有一個 `useDebugSession`；02 使用同一 `DebugPage`、`AiDebugPanel` 整合接線問答、AI 除錯與手動工具。`VideoView` 仍只有一處，相機、追蹤、鏡像及校正控制不另建副本。
- `WiringWorkspace` 保持兩個 Tab 的內容掛載，只隱藏未選取的面板；切換及收合不清除草稿、人工確認、照片紀錄或手動工具視圖，也不自動停止／重啟檢查。桌面沿用可調整寬度的左右布局，聊天及接線內容局部捲動，輸入框留在面板底部；窄／矮視窗改為上下排列。Tab 支援方向鍵、Home／End 及明確選取狀態。
- `conversation_id` 保存最近 160 則對話及檢查索引；`DebugSession` 保存一次檢查的授權、額度及工作。切頁、看圖、正常增加人工確認不新建檢查、不重設額度。
- `purpose=wiring_review` 不進行 SSH 環境診斷或安排硬體；`start_debug` 才升級。`prepare_wiring` 只能停止該案工作，其他執行者的工作需回既有執行管理處理。沒有既有工作跡象時，Pi 未上線仍可使用人工接線及看圖。
- 模型只回傳目前作品的 wire ID 與說明；後端過濾無效引用。圖面快照包含接線、GPIO／實體 Pin 標籤、排針順序、電氣版本及視覺 Profile。保存的歷史訊息仍引用原快照；與現有設計不符時僅供檢視，不能直接導向目前步驟。
- 查看圖卡的選線不修改引導焦點；只有明確導覽才回看原步驟。原人工確認、照片觀察、零件測試、整體通過分別保存。
- `ComponentTestStore` 按作品共用輪詢與操作中的狀態；引導、聊天操作卡及手動工具不建立各自的輪詢。既有測試須核對 Pi、接線鍵、接線雜湊、Profile、作品版本、測試模板及結果；TFT 另需人工確認。引用保留原時間及 run ID，不占重測次數；同設定有較新失敗時不掩蓋成舊通過。
- 逐零件測試由 `PiExecution`／`ComponentTests` 對該零件作環境 preflight；另一個零件缺 SPI／套件不會阻擋目前零件的小測試。整體試跑仍要求全作品條件。
- 真正改線、換鏡頭或改程式會撤銷過期動作；拍照及模型回覆在回存前再次核對步驟／版本。後端重啟只恢復紀錄，不重播模型請求或硬體工作。
- 「重新開始」及明確改線先核對 Pi、執行佇列、零件測試與整體試跑。需要結束本作品 AI 檢查時使用既有 `stop`，保留對話，再重新讀取工作狀態；不依賴新版 `prepare_wiring` 才能清除接線進度。沒有硬體占用的其他作品已暫停紀錄不阻擋重設，也不會被停止；其他作品仍在進行的 AI 檢查、保留中的測試及未核對的舊執行仍會阻擋。服務版本不符、狀態讀取失敗與真實工作占用分別提示，失敗時保留接線紀錄。

## 照片來源與資源上限

- 按下後從新的原始 Webcam 影格選圖，Pin 取證以約 650ms、最多九個候選為目標；記錄實際 `selection.elapsed_ms` 與候選數。這不是每次必定在 650ms 內完成的效能保證。
- 優先同幀兩端定位；同步備援各自裁切自身來源，時間差不超過 250ms。必須符合相機、來源影格、尺寸、版本及新鮮度；無有效定位時只保存新的全景。
- 原圖不含 UI 疊圖；每個視圖保留來源、裁切、旋轉、MIME、雜湊。旋正／放大只供閱讀，不新增視角或細節。API 保留 `mode`、`same_frame`、`capture_skew_ms`，分幀取證會在照片卡標示。
- 每次檢查最多六次模型呼叫（含深入定位、分析及重試）、每零件最多兩次測試、相同補拍連續最多兩次。新一輪由使用者明確按下開始，聊天歷史延續。
- 原圖與衍生圖合計最多 24 張／64MiB，結束 15 分鐘後清除。照片過期仍可讀文字及圖解；不能把圖解當成新的實拍證據。
- 對話與圖解保存在既有本機 runs 區。仍被保存訊息引用的圖解不因新增快照而被最近 32 張快照的上限移除。

API 清單與既有修復／執行條件見 [測試與除錯](test-debug-stage.md#api-與資料)。
