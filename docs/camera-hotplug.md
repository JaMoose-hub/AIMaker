# 鏡頭插拔與切換修正

2026-09-22

## 根因

- 啟動時單次預覽掃描失敗會永久隱藏「切換鏡頭」，後來接上也無法操作。
- FFmpeg 來源綁定舊名稱，原 `switch_to(index)` 不支援其他裝置。
- USB 插拔會改變編號，不能用舊 index 判斷目前鏡頭。
- 預覽探測逾時只停止等待，OpenCV 驅動可能仍在背景占用裝置。

## 使用方式

實體鏡頭模式一直保留「切換鏡頭」入口。開啟後顯示實際名稱、每兩秒更新，也能手動重新掃描。
按「使用這顆」後，選用裝置實際支援的 MJPEG 解析度，收到連續新畫面才算成功。
目前鏡頭沒有新畫面時可「重新連接這顆」。已發出的切換請求不自動重送。

裝置清單不開啟其他鏡頭，不啟用眼鏡來源，不動 Pi 執行工作、接線紀錄或辨識模型。
不同鏡頭不繼承舊 UVC 參數與鏡頭校正。切換成功後只讀取該鏡頭的控制能力，
有可調整的曝光、對焦、增益或自動白平衡才開放「智慧調整」；不會因為切換而寫入參數。
控制介面與影像來源使用同一個完整裝置 ID，避免同名鏡頭調錯台。
讀取能力失敗不影響影像串流，也不假裝支援調整。
選用設定僅存於本次後端執行期間，沒有改寫私人 config.yaml 或本機啟動工廠。

## 驗證

- 100 項相機相關後端測試通過，197 項前端測試、TypeScript 與 build 通過。
- 模擬覆蓋裝置換編號、重名、移除、舊畫面、同鏡頭重連、互斥、格式失敗與還原失敗。
- 實機 Windows 列出 HD Pro Webcam C920；從 UI 由原本已不存在的 USB camera 切至 C920，
  收到 1920×1080 新畫面；同頁即時追蹤恢復，無瀏覽器 console error。
- 實際解碼 tracking frame 並確認後續 frame_id 增加；沒有把 HTTP 200 當作影像成功。
- 尚未現場反覆拔插其他鏡頭，也未保證未測的 raw-only／虛擬鏡頭可用。

### 智慧調整退化修正

- 移除「切換後一律停用」的假設；設定沿用與能力偵測分開。
- DirectShow 控制辨識接受完整 moniker 及 FFmpeg 的冒號轉底線識別格式，
  依據 [FFmpeg dshow 原始碼](https://ffmpeg.org/doxygen/trunk/dshow_8c_source.html)；
  同名裝置仍拒絕含糊選取，不用編號或名稱取代缺失的指定 ID。
- 118 項後端相機測試通過：支援／不支援／查詢失敗、不載入舊參數、
  不寫控制項、能力查詢不破壞串流，以及 moniker 匹配。
- 實機 C920 只讀查到曝光、對焦、增益、白平衡範圍；後端 available=true，
  瀏覽器「智慧調整」可按且無 console error。
- 解碼新影格為 1920×1080，frame_id 842→857，影像內容正常。
- 本輪沒有啟動實機自動調參，不宣稱已驗證調整後的辨識改善；沒有更改 Pi 程式。
