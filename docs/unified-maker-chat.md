# 單一對話、Demo 與清除紀錄

2026-09-22。沿用原有設計生成、圖片預覽與確認套用流程，不改接線、Pi 執行管理或模型。

## 使用

- 同一輸入框可以直接提問、要求局部修改或重新設計造型，不需要選對話模式／生成方式。
- 問題或不明確要求：文字回答或追問，不產生圖片。明確修改要求：新預覽，使用者確認後才更新作品。
- 「載入 Demo 示範」讀取內建 Pi 5、HC-SR04+、MRD-TFT240 作品，不用 AI 登入或生成額度。預覽標示為示範，不冒充生成成果。
- Demo 不直接覆蓋已確認作品；若已有未確認預覽，替換前先確認。原有手動程式的覆蓋確認仍保留。
- 「清除對話」先詢問，只移除聊天訊息；作品、未確認預覽、接線紀錄、程式與未送出文字皆保留。清除後下一次要求仍能參照目前作品。
- AI 工作未完成時停用清除／Demo；重新整理接續原工作，不丟棄控制資訊或自動重新生成。

## API 與相容性

`POST /api/design/generate` 和 `/api/ai/estimate` 新增 `intent: auto`，舊的 `design`／`ask` 仍可用。
前端舊紀錄還原成 auto，但不丟棄作品、對話或執行中工作。
模型回傳嚴格結構 `{action: answer|revise|redesign, answer, proposal}`；answer 必須不帶 proposal，設計動作必須帶有效 proposal。

answer 不編譯作品、不呼叫生圖；revise 沿用既有 fixed 圖片編輯；redesign 沿用 free 重新生圖。
選擇由模型依提示詞判定，不保證所有自然語言意圖都能完全正確；最終套用仍須人工確認。
固定硬體 catalog、logic validator、圖片重試、無自動部署等既有邊界不變。
估價的 `image_generation.conditional` 說明 auto 可能需要生圖；圖片費用未包含於文字估價。
Demo 重用 `GET /api/design/demo`；清除對話為本機狀態操作，並非刪除後端生成圖片、歷史工作或雲端紀錄。
