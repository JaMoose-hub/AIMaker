# 單一對話、Demo 與清除紀錄

2026-09-22。沿用原有設計生成、圖片預覽與確認套用流程，不改接線、Pi 執行管理或模型。

## 使用

- 同一輸入框可以直接提問、要求局部修改或重新設計造型，不需要選對話模式／生成方式。
- 伺服器接受送出並回傳工作 ID 後，將原文保留在對話並清空輸入框，不等待推論／生圖完成。送出失敗保留原文；送出等待期間新輸入的草稿不會被清掉。
- 問題或不明確要求：文字回答或追問，不產生圖片。明確修改要求：新預覽，使用者確認後才更新作品。
- 「載入 Demo 示範」讀取內建 Pi 5、HC-SR04+、MRD-TFT240 作品，不用 AI 登入或生成額度。預覽標示為示範，不冒充生成成果。
- 左側對話框同步載入一組「你／Tinkro AI」示範對話，按載入時的語言選擇中英文；標示「示範對話 / Sample chat」。重複載入更新同一組示範，不刪原有真實訊息或未送出的草稿。兩則示範另計，不占原有 20 則真實訊息額度；保存重整後標記仍保留，也不會送給 AI 當作實際對話或硬體證據。
- Demo 不直接覆蓋已確認作品；若已有未確認預覽，替換前先確認。原有手動程式的覆蓋確認仍保留。
- 「清除對話」先詢問，只移除聊天訊息；作品、未確認預覽、接線紀錄、程式與未送出文字皆保留。清除後下一次要求仍能參照目前作品。
- AI 工作未完成時停用清除／Demo；重新整理接續原工作，不丟棄控制資訊或自動重新生成。
- 作品概念明確標示「未確認預覽 · vX」或「已確認作品 · vX」。「捨棄此預覽」只移除未確認版本，回到原本已確認的作品及圖片；沒有已確認作品則回到空白起始畫面，不以示範圖片替代。
- 捨棄後顯示簡短狀態提示，重新整理仍保留已確認版本標示。程式草稿、接線紀錄、聊天及未送出輸入不變；不刪除後端圖片或歷史工作。
- AI 請求送出中及推論／生圖尚未完成時停用捨棄與確認，避免尚未完成的新結果再次出現而造成誤解；這不是取消 AI 工作的操作。
- 「新作品」→「確認從頭開始」清空目前作品及圖片、預覽、聊天、程式草稿和接線進度，回到設計起始畫面；AI／零件偏好和相機設定保留。與只清聊天、只捨棄預覽不同。
  先核對舊作品的 AI／Pi 工作並將草稿備份至 `boardvision.maker.v1.before-new-project`（保留最近一份），成功保存新狀態後才更新畫面。忙碌、核對失敗或備份失敗時保留作品。不刪除後端圖片或遠端歷史。

## API 與相容性

`POST /api/design/generate` 和 `/api/ai/estimate` 新增 `intent: auto`，舊的 `design`／`ask` 仍可用。
前端舊紀錄還原成 auto，但不丟棄作品、對話或執行中工作。
模型回傳嚴格結構 `{action: answer|revise|redesign, answer, proposal}`；answer 必須不帶 proposal，設計動作必須帶有效 proposal。

answer 不編譯作品、不呼叫生圖；revise 沿用既有 fixed 圖片編輯；redesign 沿用 free 重新生圖。
選擇由模型依提示詞判定，不保證所有自然語言意圖都能完全正確；最終套用仍須人工確認。
固定硬體 catalog、logic validator、圖片重試、無自動部署等既有邊界不變。
估價的 `image_generation.conditional` 說明 auto 可能需要生圖；圖片費用未包含於文字估價。
Demo 重用 `GET /api/design/demo`；清除對話為本機狀態操作，並非刪除後端生成圖片、歷史工作或雲端紀錄。

### 2026-09-30：自然格式與簡短回覆

一般 AI 回覆預設使用 1–3 個簡短句子的自然段落，不再強制拆成 bubble list。
只有多個可執行步驟、獨立選項或比較才使用清單；有先後順序才編號。
後端 `ask`／`auto` 的實際模型提示詞與 answer schema 同步採用此規則，
一般回答以 120 個中文字或 50 個英文單字內為目標。明確要求深入說明時可展開；
重要安全條件、不確定性與尚未驗證的限制不能為縮短而省略。
這是模型的回覆指引，不保證每次模型輸出都符合固定長度。

前端保留原文的段落、條列／編號格式，不把每一句轉為清單卡片。
短回覆直接完整顯示，不再重複出現「查看完整回覆」；歷史長文與程式碼仍可展開原文。
長文預覽保留重要警告，編號也保留原本腳步號，不因省略其他內容而重新編號。
既有聊天文字與儲存格式、AI 工作、圖片預覽、人工確認與硬體操作均不變。
