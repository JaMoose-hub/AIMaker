# Webcam 與手機共用影像來源

## 目前實作：2026-10-03 共用追蹤管線

- 主畫面採「即時畫面／接線圖／接線照片」三檢視；即時畫面中的來源選單切換 Webcam／手機串流。看參考圖不切換實體來源。
- 配對手機的 WebRTC 解碼影格經 `PhoneFrameSource → CaptureService → FrameBus`，交由既有 VisionWorker、component workers 與 MotionOverlayWorker 處理。桌面不再另建手機 WebRTC viewer。
- 兩來源共用 VideoView、同張影格 JPEG＋座標、GPIO／模組腳位、接線引導和「設定 → 相機工具 → 即時追蹤」。手機的 3 Hz 是取景狀態更新，不再限制選定手機來源的影格供給；取景回饋讀共用追蹤結果而不再次推論 YOLO。
- `GET/POST /api/camera/live-source` 只接受 loopback 桌面控制。手機選取綁定配對 ID、generation、目前作品對話和新鮮影像，切換沿用既有 camera transaction：停工作執行緒、清座標、增加 runtime revision、驗證三張新影格，失敗時回復舊來源。不重載整套模型。
- Webcam 鏡像／手動偏移保留；手機以其配對世代獨立保存，不套用 Webcam 鏡頭校正。手機尺寸變更或重連世代改變時，先隱藏失效畫面與框線，使用「重新連接影像」確認新來源；不自動跳回 Webcam。
- 右側拍照倒數與 AI 影像擷取使用同一套來源綁定、時間檢查、原始影像與證據流程，記錄實際 `source=phone/device`。既有照片及接線／Pi 測試紀錄不因切換刪除；影像辨識仍不等於實體接線或功能通過。
- 實體 Webcam 的 UVC 調整和板型校正仍只在適用來源顯示／啟用，不能把 USB driver 操作套到手機。

驗證與限制見 [共用来源 QA](qa/shared-camera-2026-10-03.md)。真手機延遲、移動場景準確度、Pi／TFT 實機測試不由離線測試取代。

## 前期評估存檔（下列為整合前行為，不代表目前操作）

以下保留早期畫面整合與分離管線的決策紀錄；目前實作以上節為準。

## 本次已實作

- 手機連線入口統一放在頂部 Pi 連線左邊，不再占 AI 標題或相機工具列空間。
- 02 的「手機取景／GPIO 照片」直接放在「本步驟 2D 接線圖」同一工具列。手機面板不重複這兩個按鈕；01／03 仍可從頂部手機入口開啟面板檢視。
- 「手機取景」使用接線頁主畫面；「GPIO 照片」改為手機／Webcam 共用的主畫面照片檢視，不再只開手機面板。照片清單可切換已擷取影像；改接線步驟只更新該照片中的對應腳位，不重新拍照或呼叫 AI。
- 「相機工具」只在 Webcam 畫面提供；手機與 GPIO 照片模式不顯示。工具列移除「照片接線 POC」入口，保留其照片定位／顯示元件和後端服務。
- Webcam 新增明確的「擷取 GPIO 照片」：短暫取得既有照片工作階段、定位一次，完成或失敗都恢復連續辨識。恢復失敗保留照片並提供重試；未恢復前不允許再擷取。單純切換檢視不取得這個工作階段。手機沿用既有擷取流程，不取得 Webcam 工作階段。
- 共用照片畫面核對實際影像尺寸與定位資料，只使用同張照片座標；過去作品版本／接線輪次標示為歷史，不能高亮目前接線或視為測試通過。Webcam 新擷取另核對伺服器作品 ID／版本；遲到結果不切換新作品畫面。
- 「返回 Webcam」恢復原畫面；保留 Webcam 元件、接線確認、作品、程式及聊天。選擇手機時只將引導顯示模式切回 camera，沒有切換後端裝置。
- 同一時間只顯示一份桌面手機接收影片。關閉手機面板或收合 AI 不關主畫面；返回 Webcam／離開接線頁關閉桌面 viewer，不呼叫手機 stop API。
- 手機主畫面停用 Webcam 拍照倒數、板型校正及鏡頭選擇；截圖沿用原本手機來源、工作區、世代與照片 ID 核對。串流指標收在可展開資訊內，不虛構辨識速度或 Locked 狀態。
- 手機串流現在也顯示即時 YOLO 板框、Pi 40 個 GPIO、感測器／螢幕腳位及目前接線目標。沿用筆電既有模型、板型投影／J8 校正 helper 與 Webcam 的 PinOverlay、ComponentPinOverlay、GuideConnectionOverlay；每個手機樣本只執行一次各目錄內模型，不另開接收器或更換 Webcam 校正。
- 手機結果包含來源、配對 ID、generation、桌面 context、sample sequence 與影像尺寸。主畫面核對解碼後尺寸，不借用 Webcam 的鏡像或手動偏移。旋轉／斷線／來源不符不畫舊座標；樣本期限獨立於拍照 Locked，重複狀態與重開預覽不延長期限。
- 同作品接線步驟更新時，手機即時辨識依最新桌面清單更新，不重開手機鏡頭。這不自動採用手機的聊天／拍照工作區，也不解除原本照片核對與擷取上下文保護；必要時仍在手機加入最新工作區。
- 手機網頁先核對手機方向和解碼後的相機尺寸；直立只有本地預覽，橫放且收到真正橫向影格才發布 1920×1080（720p 為 1280×720）。不強制旋轉、裁切或拉伸；同一個輸出 track 供本地預覽、手機照片與 WebRTC，不更換後端來源管線。等待轉橫向不重開鏡頭；發布中轉回直立會停止並撤銷可拍照狀態。來源尺寸另行顯示，舊照片與座標不轉換。詳見 [手機網頁](mobile-web-prototype.md)。

## 現有管線的差異

| 項目 | Webcam | 手機 |
| --- | --- | --- |
| 即時畫面 | 後端 FrameBus → `/video`；VideoView | WebRTC → MobileRTC → 桌面 MobileVideo |
| 即時辨識 | 共用相機推論／`/ws/detections` | MobileService.on_frame → mobile_photo.preview；手機 session 狀態 |
| 校正、腳位標示 | 目前裝置／profile／runtime 的即時座標 | 手機當前樣本的 YOLO＋共用 profile 投影與即時引導；截圖後另做精細定位 |
| 保存照片 | 原 AI 除錯拍照保留；新增明確 `/api/photo-wiring/sessions` 單次 GPIO 擷取 | `/api/mobile/stream-capture` 保存後端收到的完整手機影格；或手機本地拍照 |
| 相機設定 | 裝置、曝光、解析度、板型校正 | 配對、手機鏡頭與串流設定；不使用桌面裝置設定 |

程式入口：`backend/app/main.py` 的 FrameBus、`backend/app/mobile.py` 的 on_frame／accept_preview／stream capture，以及 `frontend/src/components/MobileCompanion.tsx`、`MobileRecognitionOverlay.tsx`。手機仍沿用既有單一、latest-only WebRTC 接收路徑；手機結果只餵給手機畫面，不直接複製 Webcam 的 `/ws/detections`。

WebRTC 影片與推論資料是非同步傳輸；即時疊圖是最近有效手機樣本的引導，不保證和正在播放的每個 RTP 影格逐幀同步。現有取樣上限仍為 3 Hz，顯示／解碼 FPS 不當作 YOLO FPS。若手機或物件快速移动，應先穩定取景或擷取照片；凍結照片的 `same_frame` 才用於精細定位與照片核對。任何板框／投影脚位都不代表電氣接線或功能測試已通過。

## 建議下一步：共用選擇，分開能力

畫面選擇現已收斂為「Webcam／手機取景／GPIO 照片」及 Webcam 專用「相機工具」。這只是共用前端檢視，不表示手機已成為 FrameBus 的選定來源。手機內前後鏡頭切換和串流設定維持原功能；人工接線確認與 Pi 測試不隨檢視切換重置。

目前共用照片清單保留本次開啟期間最多 20 張；手機照片可由既有 session 在重新整理後恢复為可查看狀態，但不自動選取。Webcam 的這份前端清單尚未跨重新整理持久化，後端照片則依原服務期限保留；此變更不把舊 AI 除錯附件自動轉為新的 GPIO 擷取。

兩種來源已共用辨識模型、幾何 helper 與引導疊圖，但各自保留取樣生命週期和照片／校正路徑。若下一步需要單一 FrameBus 選定來源、統一光流追蹤與逐幀同步畫面，仍需進行下列來源抽象：

1. 定義選定來源身分（kind、裝置／session、generation、source epoch），讓畫面、推論、校正及拍照全部攜帶此身分；影格還要包含 seq、時間、尺寸與方向。
2. 以受控 adapter 將選定手機來源餵入既有最新影格管線，不再對同一功能建立重複推論；保留手機發布端、照片 API 與 session 的授權和生命週期。
3. 切換前核對拍照／校正／AI 照片工作；切換後廢止舊來源的座標、倒數任務及即時可拍照狀態。舊照片和歷史保留，但不能當作新來源證據。
4. 手機旋轉、鏡頭切換、斷線／重連都提升世代或 epoch，重新取得該來源校正；影像與座標身分不符時不畫腳位。
5. 做實機來源切換、旋轉、斷線、拍照一致性、推論負載與手機 Locked 新鮮度驗證，再啟用共用即時疊圖。

本次未改成單一 FrameBus 來源，也未宣稱手機光流／校正／逐幀同步與 Webcam 等效。瀏覽器驗證使用隔離的合成影片，不能替代實機串流、延遲或腳位準確度驗證。詳見 [驗證紀錄](qa/phone-recognition-2026-10-03.md)。
