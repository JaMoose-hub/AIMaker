1. 手持零件時，能在約定的操作距離、角度及不同背景下辨識與追蹤。
2. 接線時不因局部遮擋就讓整組標記消失，手移開後能恢復。
3. 截圖保留正確方向及接頭細節，雲端能給出直覺、可核對的接線判讀。
4. 展示流程簡短：設計 → Blueprint → 接線引導 → AI 檢查（可選）→ 部署。

## Demo 簡化原則

- 不新增登入、審批、斷電確認勾選、接線準備精靈等流程。
- 沒辨識到也能手動開始、上一步、下一步、重新接線；有新相機照片就能按 AI 檢查。
- AI 檢查可跳過；辨識成功、AI 判對或人工接線勾選，不作為部署按鈕的前提。
- 不因未跑完整套驗收，就封鎖使用者試 Demo；本檔是開發追蹤表，不是操作門禁。
- 照片不足只給一句具體補拍提示，提供重拍；不用長篇提醒。
- 簡化操作不等於造假：舊框不冒充即時定位，畫質分数不冒充接線正確率，模擬輸出不冒充硬體結果。
- 相機無新影格、SSH 連不上、缺驅動等實際錯誤仍需呈現，避免使用者不知道卡在哪。
- 本計畫不要求移除電壓保護電路或忽略未知硬體規格。錯接照片用不供電的接線樣本取得，不需額外增加軟體確認步驟。

## 1. 建立目前環境基準

**目的：**先分辨「找不到物件」「框不準」「Pin 不準」「畫面卡」，避免混在一起調參數。

**做法：**

1. 固定相機位置，記錄相機／解析度、對焦與曝光設定、桌面、光線、程式／模型／Profile 版本。
2. 四零件分別平放中央，再放到畫面左右側；腳位列完整露出，各錄 10 秒。
3. 人工指出正確零件邊界、排針方向及代表性 Pin；不能拿系統自己的投影當答案。
4. 記錄辨識可用率、框／Pin 漂移、取得定位時間、串流更新率及延遲。
5. 優先修正模糊、過小、嚴重反光及設定錯誤；先不直接降低辨識門檻。

**完成條件：**四零件各有一份基準影像與量測；Demo正常靜止畫面目標辨識可用率 ≥90%。不達標保留失敗基準，依最新限次規則推進，不無限重拍。

- [ ] 相機與版本設定記錄完成。
- [ ] 四零件各自基準完成，包含人工 Pin 參考位置。
- [ ] 失敗原因分類、修正前後比較完成。

**使用者配合：**擺放零件、露出腳位並核對方向。**是否需訓練：**否。

## 2. 跨背景辨識

**目的：**零件要靠自身外觀辨識，不依賴目前桌面。

**做法：**

1. 相機、光線、距離先不變，只更換白色、深色、木紋／花紋、雜物／線材背景。
2. 每種零件在每個背景測兩條路徑：A. 清除追蹤暫存後直接找到零件；B. 已鎖定後換背景，再移出／移回畫面。清除暫存不清除作品或接線進度。
3. 正式測試每種背景／每種零件各做 10 次首次取得定位，另錄 10 秒持續追蹤。
4. 加拍只有背景、沒有零件的負例，檢查是否將雜物誤認成零件。
5. 依原因修正：背景特徵干擾→縮小追蹤取樣至板體；顏色規則脆弱→檢查局部判定；模型根本找不到→進入補資料分支。

**完成條件：**各組首次取得定位至少 9/10 次在 2 秒內；持續可見時追蹤可用率 ≥90%；每種背景 10 秒無零件測試不得出現持續 1 秒以上的假鎖定。完整跨背景矩陣列後續強化，所有失敗仍需記錄，不只報總平均。

- [ ] 四背景 × 四零件 × 兩路徑測試完成。
- [ ] 無零件背景負例完成。
- [ ] 修正後重測，或列出需要補資料的具體情境。

**使用者配合：**換背景、擺放與移入移出。**是否需訓練：**視失敗原因，先不預設需要。

## 3. 跨光線與實際環境

**目的：**換場地後不用反覆手動改一堆參數。

**做法：**

1. 先同背景測明亮、一般室內、偏暗與暖／冷色光；分開記錄亮度與色溫，不一次改所有條件。
2. 四零件各錄 10 秒，再每種條件做 10 次首次取得定位。
3. 另外換至少一個實際環境，四零件重新開始辨識；不能只帶著原有鎖定過去。
4. 檢查自動曝光造成的拖影、固定焦距範圍、白平衡對顏色規則的影響。
5. 選出一般展場能使用的預設設定，必要時提供一個簡單「展場設定」，不做繁複調校精靈。

**完成條件：**在記錄的可用光線範圍內，達成第 2 項取得定位與持續追蹤目標；第二個實際環境不需改程式。超出可用範圍的條件要明列，不宣稱所有光線皆可。

- [ ] 四零件的光線／色溫測試完成。
- [ ] 第二環境測試完成。
- [ ] 預設成像設定及已知限制記錄完成。

**使用者配合：**改光線、搬到另一個環境。**是否需訓練：**成像設定先處理，剩餘模型問題才補資料。

## 4. 相機校正與 GPIO／零件 Pin 對齊

**目的：**框穩定之外，標記必須落到正確腳，而不是隔壁腳。

**做法：**

1. 準備現有校正流程要求的校正圖；依工具要求記錄圖案尺寸，拍摄覆盖畫面中心、邊緣與不同傾角的校正影像。
2. 保存與實際解析度、鏡頭設定匹配的校正結果，重新讀取確認生效。改變焦距／解析度後需檢查是否仍適用。
3. Pi 核對 J8 的 Pin 1、兩排方向、頭尾及中間位置；三模組核對整列 Pin 順序。資料仍沿用既有 Profile，不建第二份腳位表。
4. 逐零件測平放及約 30°／45°／60° 傾斜；只对實際看得見的 Pin 評估精度。
5. 每件至少 20 張清楚照片，以人工標記比較位置誤差，按照片中的相鄰腳距正規化；錯排、反向與錯腳單獨計數。
6. 若仍不準，依序檢查鏡像／縮放座標、校正參數、板體姿態、排針局部定位及高度差；不能只靠平滑掩蓋偏移。

**完成條件：**有效校正載入；可見 Pin 位置誤差 p95 ≤相鄰腳距的 1/4，固定清楚照片中無錯排／方向顛倒。這是待達成目標，不是現有離線變形誤差的換算。

- [ ] 校正圖、校正結果與設定記錄完成。
- [ ] Pi 40-Pin 排列及三模組腳位順序核對完成。
- [ ] 四零件實拍位置誤差與修正後比較完成。

**使用者配合：**拿校正圖、擺放角度、核對實際腳位。**是否需訓練：**校正／幾何先做，姿態關鍵點模型不足才另評估。

## 5. 手持、多角度與遮擋

**目的：**正常拿取時穩定，局部遮擋不造成全部 Pin 消失。

**做法：**

1. 四零件各做平面旋轉 0°／90°／180°／270°、連續旋轉、傾斜、靠近／遠離、慢移／快速移動。
2. 各測遮住約 1/4、1/2 板體、只遮住 Pin 區、完全遮住約 1 秒，再移開手；每種動作至少 5 次。
3. 同時記錄物件是否仍追得到、可見 Pin 是否保留、被遮住區域是否誤顯示、恢復時間。
4. 檢查是否學到手／背景特徵，以及接近側面時姿態是否失真；回放失敗片段調整。
5. 背面／近乎側面分開測物件身分辨識，不要求畫出不可見的正面 GPIO；列出實際支持範圍，不能宣稱無條件任何角度。

**完成條件：**約定可見操作範圍內追蹤可用率 ≥90%；重新露出後恢復時間 p95 ≤1 秒；完全遮擋不輸出舊精準標記。每件均需真實錄影，不能用同一張合成紋理代替。完整手持矩陣列後續強化，不作今天接線流程前置。

- [ ] 四零件手持動作與角度範圍記錄完成。
- [ ] 各種遮擋／恢復實拍完成。
- [ ] 固定失敗回放及修正前後比較完成。

**使用者配合：**拿取、旋轉、遮擋。**是否需訓練：**追蹤邏輯先做，無法首次辨識的視角才補資料。

## 6. 插拔線與接線後外觀更新

**目的：**加入黑色接頭與線材後，不一直失去定位或無法恢復。

**做法：**

1. 三模組逐一與 Pi 組成接線場景，每組包含 Pi 端與模組端。
2. 依「未插線 → 插一條 → 插多條 → 拔除 → 重插」錄影；每端至少 5 次插拔。
3. 加測接頭附近有手、線交叉、線經過板面、手移開但接頭仍留下的情況。
4. 確認未改變區域持續追蹤；改變區域使用新的有效影像重新取得支持，不沿用遮擋模板，也不永久隱藏。
5. 確認上一步、下一步、重新接線、收合／展開，不會清掉不相關進度或卡住操作。

**完成條件：**所有端點完成測試；手移開且接點可見後，定位恢復 p95 ≤1 秒；新接頭外觀不造成永久失效。無辨識時依然可手動繼續，視覺狀態與人工進度分開。

- [ ] HC ↔ Pi 插拔測試完成。
- [ ] HW ↔ Pi 插拔測試完成。
- [ ] TFT ↔ Pi 插拔測試完成。
- [ ] 引導導航與重新接線操作通過。

**使用者配合：**插拔與核對實際端點。**是否需訓練：**外觀更新邏輯先做，模型對已接線外觀失效才補資料。

## 7. 四零件同時辨識與效能

**目的：**不是只有一個零件時好用；四個都在場也要公平更新、不誤選同名 Pin。

**做法：**

1. 四件一起入鏡，先分開擺放，再靠近、部分重疊、加入線材；確認每件分別顯示正確身分。
2. 逐一拿起其中一件，其他不動；確認其他物件不受牽連。
3. 切換三模組接線目標，檢查 GND／SDA 等同名腳位不串到另一件。
4. 連續測 5 分鐘，記錄每件辨識可用率、更新間隔、相機影格年齡、CPU／GPU／記憶體，以及顯示更新率。
5. 依瓶頸處理模型排程、重複影格、恢復搜尋預算、前後端傳輸；不盲目把所有小運算搬到 CUDA。

**完成條件：**四件可見且未遮擋時各自可用率 ≥90%；顯示更新率目標 ≥25 FPS，相機到顯示延遲 p95 目標 ≤150ms（須有量測方法，不能用推論耗時代替）；無串錯目標、長時間飢餓或持續記憶體成長。

- [ ] 四件同場與逐件移動測試完成。
- [ ] 同名 Pin 目標與引導切換通過。
- [ ] 5 分鐘效能報告與瓶頸修正完成。

**使用者配合：**擺放四件、移動其中一件。**是否需訓練：**排程與效能不需；重疊辨識不足另評估資料。

## 8. 雲端接線判讀驗收

**目的：**知道接頭有沒有插上、插在哪一腳，而不只是說對線色。

**做法：**

1. 用 HC ↔ Pi、HW ↔ Pi、TFT ↔ Pi 三組測試，涵蓋 Pi 與每個模組的端點。
2. 每組先準備 20 個有人工答案的清楚案例：正確接線 10、相鄰錯腳 5、未插接頭 5；另加 5 個遮擋／交叉／方向不清案例。Pi 端與模組端都要涵蓋錯接，不只錯在同一端。
3. 每例保存實際接線答案、原圖、送出的圖、Profile／目標、模型與推理設定、回覆和耗時。圖片使用案例編號，不以檔名洩漏答案给模型。
4. 先人工核對裁圖：是否同一時刻、方向完整、接頭與線材出口在畫面；再評雲端接頭／腳號／同線路判斷。
5. 依原因改善裁圖或提示；比較模型時使用同一批照片與答案，記錄額外用量，不默默換模型。
6. UI 保持短版：「結果 → 兩端看見什麼 → 下一個動作」；詳細證據收合。未看清楚只要求缺少的那個視角。

**完成條件：**每組清楚案例至少 18/20 正確；不確定列入未答對，不從分母剔除；錯腳與未插被判通過的案例必須單列。模糊案例要誠實保留不確定，不能因相同線色就判接對。先完成一組端到端小批檢查再補數量，不因完整矩陣未齊阻擋Demo。小樣本不宣稱統計上已保證普遍90%準確。

- [ ] 三組人工答案與固定照片集完成。
- [ ] 新截圖品質現場驗收完成。
- [ ] 各端點／各案例類別混淆結果及耗時完成。
- [ ] 提示、裁圖或模型比較後重測完成。
- [ ] 回覆 UI 簡短易讀，檢查可跳過且不阻擋下一步。

**使用者配合：**準備接線樣本、核對答案。**是否需訓練：**先改善輸入／提示；此階段不預設微調雲端模型。圖片檢查不能證明導通或功能。

## 9. 展覽完整流程、重啟與重連

**目的：**一般使用者能順暢示範，重新開程式也不需要工程師補救。

**做法：**

1. 使用固定四零件範圍，跑設計 → Blueprint → 接線引導 → 可選 AI 檢查 → 部署；做至少 3 次完整流程。
2. 測無定位也可操作、跳過 AI、返回前階段、重新接線、程式草稿保留；不用重新填一堆確認。
3. 連續重啟程式 10 次，每次四零件都在畫面：確認模型載入、登入狀態、相機與各零件首次定位，記錄失敗原因。
4. 相機拔插／重新連接 3 次；場景變更後不沿用舊定位，作品與人工進度不被清除。
5. 部署測試包含首次部署、修改文字再部署、單實例、語法錯誤與執行例外；不得把「已執行」直接寫成「硬體功能正常」。
6. HC 測距、HW 姿態、TFT 顯示分開記錄。HW／TFT 規格或驅動未確認時，視覺及接線展示照做，功能標待完成，不刪掉這兩件，也不用假讀值宣稱完成。
7. 最後四件在場連續操作 20 分鐘，確認不卡住、無持續累積延遲，並留下簡短 Demo 操作稿。

**完成條件：**3 次完整操作通過；10/10 重啟及 3/3 相機重連能恢復；20 分鐘可連續展示。硬體功能分項列出真實結果；未測／待規格的項目不可勾選為完成，但不封鎖視覺 Demo。

- [ ] 3 次完整流程與簡化操作驗收完成。
- [ ] 10 次重啟：四件模型與定位逐件核對完成。
- [ ] 3 次相機重連與資料保留通過。
- [ ] Pi 部署、重新部署與错误顯示通過。
- [ ] HC 真實功能完成。
- [ ] HW 晶片／驅動確認及真實功能完成。
- [ ] TFT 規格／驅動確認及真實功能完成。
- [ ] 20 分鐘展示與 Demo 操作稿完成。

**使用者配合：**完整操作、相機拔插、硬體結果核對。**是否需訓練：**通常不需。

## 後續追加：Webcam 第一人稱視角驗證（原九階段完成後執行）

**順序：** 先完成原九階段的修正與驗收，不插入本分支、不要求現在改鏡頭。之後用既有 webcam 建立第一人稱基準，再重用第 2～9 階段的方法驗證；只有失敗證據需要時才補訓練。下列「眼鏡來源／眼鏡案例」均指第一人稱 webcam 取景。每次只請使用者做一個擺放或視角動作，等待「好了」再採樣。

- [ ] 記錄既有 webcam 的第一人稱安裝位置、朝向、工作距離、解析度／FPS、鏡像／旋轉；先固定於接近眼睛位置取景，再測視角移動，不以智慧眼鏡型號或硬體採購作前提。
