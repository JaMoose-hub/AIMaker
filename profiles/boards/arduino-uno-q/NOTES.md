# arduino-uno-q profile — data provenance & notes

Generated by `tools/gen_pin_table.py` + `tools/render_reference.py`.
Do not hand-edit `board.json`; edit the generator table and re-run.

## Files

| file | produced by | purpose |
|---|---|---|
| `board.json` | `gen_pin_table.py` (reference block re-embedded by `render_reference.py`) | pin/capability database, validated against `schemas/board-profile.schema.json` AND `backend/app/profiles/models.py` on every generation |
| `reference_synthetic.png` | `render_reference.py` | deterministic (seed 42) orthographic top view, 2401x1868 px, exactly 35 px/mm, `mm_to_px = [[35,0,0],[0,35,0],[0,0,1]]` |
| `verify_overlay.png` | `render_reference.py` | reference + every pin circled/labelled straight from `board.json` (visual QA) |
| `calibration_overlay.png` | `calibrate_reference.py` | verification overlay from the latest calibration run (currently: the headless self-test against the synthetic reference) |
| `features.npz` | `calibrate_reference.py` | pre-computed ORB (nfeatures=4000) + SIFT keypoints/descriptors of the reference image; keys: `orb_pts/size/angle/response/octave/desc`, same for `sift_*`, `image_shape` (h, w) |

When a real board photo is calibrated (`tools/calibrate_reference.py`), the
`reference` block in `board.json` and `features.npz` are replaced; the
previous `board.json` is backed up as `board.json.bak-<timestamp>`.

## Geometry provenance (verified 2026-07-27)

* The UNO Q keeps the exact UNO R3 form factor (shield compatible; official
  headers JDIGITAL 18-pin / JANALOG 14-pin). All drill coordinates were
  extracted from the official Arduino UNO R3 Eagle board file
  `arduino_Uno_Rev3-02-TH.brd` (Eagle 6.1 XML; mirror:
  github.com/una1veritas/EagleDocs), elements IOH/IOL/POWER/AD + 1XN package
  pad offsets, nets cross-checked (e.g. IOH pad10 = AD5/SCL, POWER pad1
  unconnected). Eagle origin is the lower-left corner; converted to the
  profile's top-left/y-down frame via `y = 53.34 - y_eagle`.
* Rows: top row y = 2.54 mm, bottom row y = 50.80 mm. Pitch 2.54 mm.
  Top: SCL 18.796 .. D8 41.656 | 0.16 in gap | D7 45.72 .. D0 63.50.
  Bottom: BOOT 27.94 .. VIN 45.72 | 0.20 in gap | A0 50.80 .. A5 63.50.
* Mounting holes (dia 3.2 mm): (15.24, 2.54), (66.04, 17.78), (66.04, 45.72),
  (13.97, 50.80) — calibration click order TL, TR, BR, BL.
* Mounting-hole coordinates live in `tools/uno_q_geometry.py`, not in
  `board.json` (the profile schema has no hole field).
* `header_top_z_mm = 8.5` — standard female header height above the PCB.

## Capability provenance (verified 2026-07-27)

Primary source: Arduino UNO Q user manual (arduino/docs-content markdown,
the source of docs.arduino.cc/tutorials/uno-q/user-manual):

* PWM: D3, D5, D6, D9, D10, D11 — frequency fixed at 500 Hz.
* UART (uart0/USART1): D0 = RX (PB7), D1 = TX (PB6).
* SPI (spi0) IS carried by the header pins: D10 SS (PB9), D11 MOSI (PB15),
  D12 MISO (PB14), D13 SCK (PB13).
* I2C: Wire = dedicated SDA/SCL header pins (Arduino D20 = PB11 SDA,
  D21 = PB10 SCL). A4 = PC1 "SDA2", A5 = PC0 "SCL2" — on the UNO Q these are
  a SECOND STM32 I2C, not hard-wired to the dedicated SDA/SCL pins (unlike
  the classic UNO). Encoded: all four in bus `i2c0` per the app contract,
  with 優先使用專用 SDA/SCL notes on the bus and on the A4/A5 capabilities
  spelling out the distinction. (Qwiic = Wire1/I2C4 on PD12/PD13, not on the
  headers — not encoded.)
* ADC: A0-A5, up to 14-bit (0-16383) via `analogReadResolution(14)`;
  `analogRead` DEFAULTS to 10-bit (0-1023) on the UNO Q ArduinoCore-zephyr.
  Default reference 3.3 V, external reference via AREF
  (`analogReference(AR_EXTERNAL)`). A0/A1 also DAC; A2/A3 also OPAMP
  IN+/IN-; D3 OPAMP output; D4/D5 FDCAN TX/RX alternates.
* A0/A1 are ADC inputs only (official power-spec tutorial: "JANALOG
  (A0/A1): ADC inputs only. Do not source or sink DC current into these
  pins.") — encoded with no `max_current_ma` and a do-not-drive-loads
  warning. Their GPIO/DAC capability entries stay (official user manual
  lists GPIO/DAC).
* MCU STM32U585 (Arm Cortex-M33 @ 160 MHz, Zephyr OS); MPU Qualcomm QRB2210
  (4x Cortex-A53 @ 2.0 GHz, Debian Linux). 8x13 blue LED matrix driven by
  the STM32.
* 3.3 V logic; 5 V tolerance is encoded PER PIN (official datasheet §9.6 +
  full-pinout PDF + power-spec tutorial):
  - FT-type digital I/O (D0-D2, D4-D13, SDA, SCL):
    `five_volt_tolerant: true` — 5 V tolerant as digital INPUTS only,
    outputs are always 3.3 V; severity-`warning` note recommending level
    shifting and forbidding driving 5 V-level inputs from this board.
  - D3 (PB0): TT-type pad, absolute max 3.6 V in every mode —
    `five_volt_tolerant: false` + danger warning.
  - A0/A1: direct ADC pins, never 5 V tolerant —
    `five_volt_tolerant: false` + danger warning (divide down > 3.3 V).
  - A2-A5: headline use is analog — `five_volt_tolerant: false` +
    severity-`warning` note (not 5 V tolerant in ADC mode; official docs
    mark them 5 V tolerant only as digital inputs).
  - AREF: not 5 V tolerant, keeps the blanket 3.3 V danger warning.
  The board-level `five_volt_tolerant: false` is kept as the conservative
  headline statement (drives the CapabilityCard board notice).
* Max current 20 mA/pin (200 mA total): from the CWTI-Ltd
  arduino_uno_q_knowledge_base pin reference (community source; consistent
  with STM32 I/O limits). Encoded as `max_current_ma: 20` — except A0/A1,
  which must not source/sink DC current and carry no `max_current_ma`.
* Interrupts: STM32U5 EXTI — attachInterrupt available on the header GPIOs;
  encoded as an `interrupt` capability on D0-D13.

## Open items / honest uncertainties

* **JANALOG position 1 — RESOLVED (2026-07-27)**: it is **BOOT**
  (MCU_BOOT0), not NC. Resolved via the official ABX00162 full-pinout PDF,
  whose power block reads "BOOT IOREF RESET +3V3 +5V GND GND VIN", and the
  datasheet JANALOG pin map: "1 | BOOT | MCU_BOOT0 | Boot strap | 3.3 V".
  (The classic UNO R3 kept this position NC.) Encoded as pin id `BOOT`,
  silkscreen `BOOT`, capability `boot`, with a danger warning: do not pull
  it high during boot/reset or the STM32 enters the system bootloader
  instead of running the sketch.
* IOREF is encoded as a 3.3 V output (definitionally the I/O reference of a
  3.3 V board; the R3 tied it to its 5 V rail). Not measured on hardware.
* PWM examples mention servos; note the UNO Q analogWrite PWM is fixed at
  500 Hz — hobby servos should use the Servo library, which drives pins at
  the proper 50 Hz.
